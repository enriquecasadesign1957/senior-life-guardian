## Direct webhook from Grafana to WakeUp Dev

Grafana’s webhook payload can be piped straight to WakeUp Dev’s `/v1/alert` endpoint. The platform accepts the JSON payload, creates a voice call, and waits for a single‑digit “1” ACK. Because the call is never answered, you avoid carrier pickup fees while still confirming that the alert was seen.

```bash
curl -X POST https://api.wakeupdev.com/v1/alert \
  -H "Content-Type: application/json" \
  -H "x-api-key: $WAKEUP_API_KEY" \
  -d '{
    "title": "CPU usage high",
    "message": "Node‑01 CPU > 90% for 5m",
    "severity": "critical",
    "source": "grafana",
    "routing": {"team": "infra"}
}'
```

## Reducing fatigue with a single‑digit ACK

When the call arrives, the Twilio cascade plays a concise prompt: “Press 1 to acknowledge this alert.” The digit is captured by WakeUp Dev, the alert is marked resolved in Grafana, and no further escalation occurs. This pattern removes the need for multiple chat channels or email threads that often drown engineers in noise.

- One‑digit ACK eliminates the “pick‑up” step.
- Unlimited seats mean every on‑call engineer can be added without extra cost.
- Pay‑per‑voice‑alert model scales with actual incidents, not headcount.

## Operational checklist

- Configure Grafana webhook URL: `https://api.wakeupdev.com/v1/alert`.
- Store the API key in a secret manager and reference it as `$WAKEUP_API_KEY`.
- Map Grafana alert labels to WakeUp Dev routing fields.
- Test the flow with a low‑severity alert before promoting to production.

By treating the voice ACK as the final state transition, you close the loop inside Grafana without additional tooling. Teams report a measurable drop in missed alerts and a clearer on‑call schedule.
