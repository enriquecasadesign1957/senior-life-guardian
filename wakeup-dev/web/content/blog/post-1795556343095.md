## Cost Comparison

Per‑seat licensing forces teams to pay for every on‑call member, even when the seat sits idle. For a 20‑person squad that’s 20 × $X/month, a cost that scales linearly with team size.

## How Pay‑Per‑Alert Works

WakeUp Dev removes the per‑seat burden by charging only for the voice alerts that actually reach a responder. Each alert is a single API call to POST https://api.wakeupdev.com/v1/alert with your x‑api‑key. The cost is proportional to the number of alerts, not the number of seats.

- Unlimited seats: add or remove team members without changing the bill.
- Pay‑per‑alert: $0.02 per voice alert delivered.
- No per‑seat tax: the platform’s pricing model is flat across all seats.

## Implementation Example

```bash
curl -X POST https://api.wakeupdev.com/v1/alert \
  -H \"x-api-key: YOUR_KEY\" \
  -H \"Content-Type: application/json\" \
  -d '{
    \"message\": \"Database latency spike detected\",
    \"severity\": \"critical\",
    \"source\": \"grafana\",
    \"metadata\": {
      \"alert_id\": \"db-latency-42\"
    }
  }'
```

When Grafana fires an alert, the webhook payload is forwarded to WakeUp Dev, which then initiates a voice call to the on‑call rotation. The responder can ACK by pressing 1, ending the call instantly.

## ROI & Savings

A typical 30‑person team that receives 5 k alerts per month can cut its on‑call budget from $4,800 (20 × $240) to roughly $100 (5 k × $0.02). The savings grow as alert volume rises, while the unlimited‑seat model keeps staffing flexible.

WakeUp Dev’s pay‑per‑alert pricing aligns cost with actual usage, giving SREs a clear financial incentive to optimize alert rules and reduce noise.
