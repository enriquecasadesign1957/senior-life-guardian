Integrating Grafana alerts into a voice‑first on‑call platform can dramatically reduce the time between detection and acknowledgement. WakeUp Dev’s webhook‑first architecture lets you push alerts directly from Grafana to a phone cascade, eliminating the need for email or chat notifications that often get buried.

## Grafana Webhook to WakeUp Dev
Grafana’s webhook integration is straightforward: configure the alert rule to POST to `https://api.wakeupdev.com/v1/alert` with the `x-api-key` header. The payload can be the default JSON or a custom structure; WakeUp Dev normalises the fields and forwards the alert to the appropriate on‑call schedule.

```bash
curl -X POST https://api.wakeupdev.com/v1/alert \
  -H "x-api-key: YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{"message":"CPU > 90%","severity":"critical"}'
```

The webhook can also include a `routing_key` to target a specific team or role, allowing fine‑grained escalation paths.

## Voice ACK and Digit‑1 Confirmation
When the alert is received, WakeUp Dev initiates a Twilio call to the on‑call engineer. The call plays a concise alert summary and waits for a single digit. A TwiML snippet that captures a “1” to acknowledge looks like this:

```xml
<Response>
  <Say voice="alice">Alert: CPU usage exceeded 90%. Press 1 to acknowledge.</Say>
  <Gather numDigits="1" action="/ack" method="POST">
    <Say>Press 1 to acknowledge.</Say>
  </Gather>
  <Say>We did not receive an acknowledgement. Please try again later.</Say>
</Response>
```

The `/ack` endpoint records the acknowledgement and updates the alert status in WakeUp Dev’s dashboard. Because the call is the only channel, engineers can focus on the alert without switching contexts.
